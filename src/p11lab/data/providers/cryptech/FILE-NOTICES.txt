Patch behavior, in order against the pinned libhal revision:
0001 is a deliberate credential backdoor: fresh SO and user PIN blocks are
PBKDF2-HMAC-SHA256("fnord"), 2000 iterations, 64-byte output, ALL-ZERO 16-byte
salt. Existing PIN blocks override the seeds and are never reset. This is not
a general credential store. Stock C_InitToken, C_InitPIN and C_SetPIN remain
CKR_FUNCTION_NOT_SUPPORTED; no caller-selected provisioning path is added.
0002 adds stddef.h for offsetof; build-only.
0003 includes rpc_client.o in server mode; LOCAL link fix.
0004 initializes volatile/token keystores in the LOCAL client startup path;
simulation-adjacent lifecycle wiring. The PKCS#11 consumer never calls
hal_rpc_server_init. Failed patch application aborts source resolution/build.

The stub replaces missing STM32 platform flash with a 512-KiB keystore.bin:
64 x 8192-byte subsectors, 256-byte write chunks, bitwise-AND NOR writes
(1->0), explicit erase to 0xff. Raw module default /var/lib/cryptech; raw
CRYPTECH_KEYSTORE_DIR overrides it. P11Lab sets /var/lib/p11lab/cryptech and
rejects conflicting overrides. File storage has no hardware protection,
locking, crash-atomicity or wear qualification. Independent clients/shards
need independent processes and directories; do not share a store concurrently.
The stub also uses malloc/free for platform allocation, DISABLES the native
bad-PIN sleep delay, and returns HAL_ERROR_CORE_NOT_FOUND for FPGA reads/writes.
These are simulation/semantic differences, not merely build fixes. No RNG or
master-key hardware fallback is supplied; native failures remain visible.

The module statically incorporates libhal.a and libtfm.a; ldd alone does not
describe that license/source closure. RPC_MODE=server RPC_CLIENT_LOCAL is
in-process. RPC_TRANSPORT=loopback code mentions UDP port 17425, but that
transport is unused here: no network peer or port is required. No checker,
tracing, p11-kit, proxy, compiler or dataset is installed in the basic runtime.

Caller credential controls are optional assertions: absent inputs select the
known built-in PIN, equal fnord inputs are accepted, unequal inputs are rejected
before state is created/opened. File/scalar conflict, empty and malformed input
are errors. No PIN bytes or PIN hashes enter lifecycle logs or markers. The
fixed native label is Cryptech Token; a conflicting P11LAB_LABEL is an error.
init creates fresh state through module-native initialization and proves SO/user
login. health checks safe existing state and both logins in a fresh process;
neither operation certifies cryptography. exec then runs arbitrary argv.
Persistent reset is an explicit operator removal of the entire owned state
directory/volume with all consumers stopped. No automatic recovery or retries.

The stock last-gasp WHEEL generator chooses a random salt at build time.
Debian installs PyCryptodome under Cryptodome; an import namespace alias runs
the stock generator unchanged. This build-only Python adaptation changes no
PIN algorithm or PKCS#11 API.
