SDK patch patches/0001-pico-keys-sdk-frozen-mbedtls.patch is
P11Lab-authored (SPDX-License-Identifier: Apache-2.0, same as the
recipe), byte-identical to the opensc-pico recipe's patch for the
same frozen SDK revision. It forces the SDK configure self-update
flag off with an explanatory status line, so the frozen vendored
mbedTLS v3.6.6 tree is used exactly as vendored instead of being
probed, fetched over the network, partially deleted and checked
out at configure time. Without it the build would require
build-time network access and mutate its own inputs. Build-freeze
provisioning extension, not a semantic change: the built library
sources are exactly the v3.6.6 tree the unpatched network build
produces after its silent upgrade. A declared patch that fails to
apply fails source resolution before any build starts.

pico-hsm patch patches/0002-pico-hsm-termca-bare-cvc.patch is
P11Lab-authored for this recipe (SPDX-License-Identifier:
Apache-2.0, same as the recipe). The v6.6 INITIALIZE handler
stores EF_TERMCA (FID 2F02) as the 0x67-wrapped device
authentication object concatenated with the terminal CA CVC; no
consumer expects that layout. The module under test parses the
file as one CVC optionally followed by the issuer CA CVC and
refuses the token otherwise, the firmware's own PUK-store and
XKEK code expects a CVC at offset 0, and upstream pico-hsm master
already writes a bare CVC here. The patch stores exactly the
generated terminal CA CVC. Simulation-fidelity fix: without it a
freshly initialized card presents no token to the module under
test. A declared patch that fails to apply fails source
resolution before any build starts.

The reference ctbcs unistd patch
(docker/sc-hsm-embedded/patches/0001-ctbcs-include-unistd.patch)
was evaluated and NOT migrated: its file (src/ctccid/ctbcs.c)
is outside the default PC/SC build closure (SUBDIRS adds ctccid
only under ENABLE_CTAPI), so the patch would touch code this
recipe never compiles. The reference applies it redundantly.
