Original P11Lab Dockerfile, entrypoint.sh, provision.c,
runtime-debs.txt and the SDK build-freeze patch: Apache-2.0, root
LICENSE. These separate orchestration modules do not relicense
OpenSC, pico-hsm, the SDK, mbedTLS, mlkem, tinycbor, vsmartcard or
the Debian closure. No reference script text, credentials or
initialized flash data is copied. The pkcs11-check-ws reference lane
(docker/pico-hsm) informed only the pcscd/vpcd/emulator topology
and the key-provisioning roster shape; this recipe re-derives
sources, pins, supervision and the credential model, fabricates a
fresh flash at runtime, provisions caller PINs over a pty where the
reference reuses baked credentials, and asserts every provisioning
outcome where the reference tolerates keygen failure. No simulated
PKCS#11 calls and no silent behavior changes exist.

SDK patch patches/0001-pico-keys-sdk-frozen-mbedtls.patch is
P11Lab-authored for this recipe (SPDX-License-Identifier:
Apache-2.0, same as the recipe). It forces the SDK configure
self-update flag off with an explanatory status line, so the
frozen vendored mbedTLS v3.6.6 tree is used exactly as vendored
instead of being probed, fetched over the network, partially
deleted and checked out at configure time. Without it the build
would require build-time network access and mutate its own
inputs. Build-freeze provisioning extension, not a semantic
change: the built library sources are exactly the v3.6.6 tree the
unpatched network build produces after its silent upgrade. A
declared patch that fails to apply fails source resolution before
any build starts.
