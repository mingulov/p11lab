PAL/config deltas (PKCS#11 semantic changes, not mere provisioning):
- Replaces POSIX current-working-directory files and fixed configured labels
  with heap copies in one static store per loaded library instance. State is
  shared across sessions and survives C_Finalize/C_Initialize in that instance;
  process exit or unload destroys access. Fresh independent exec/process starts
  empty. Fork could inherit a memory snapshot; it is not an independent token.
  No shared-memory, database, persistent token or restart-reopen claim.
- Exact byte labels of length 1..32 (including embedded NULs at the PAL boundary)
  replace stock NUL-terminated configured-label matching. Same label overwrites
  data and reuses its PAL handle, regardless of object class. Different labels
  take the first free handle. Label remains required; upstream label-only search,
  token-only object handling and template parsing remain unchanged.
- 256 PAL entries (2 * 128) versus eight fixed stock mappings; upstream object
  list capacity 128 (previous config 6), max sessions 32 (previous config 10).
  Allocation/full-store/invalid SaveObject returns invalid handle, propagated
  by upstream as native errors, including CKR_DEVICE_MEMORY. No retries.
- Mutex-protected PAL operations; value reads return allocated snapshots, not
  borrowed storage. Destroy frees and zeros the entry, permits handle reuse;
  PAL_DESTROY_SUPPORTED=1 replaces stock destroy-via-zeroing fallback. Heap data
  is not securely erased before free. The PAL is not an authentication boundary.
- Privacy is inferred from DER first child tag (INTEGER => private); stock PAL
  instead used fixed key labels. This changes CKA_CLASS/CKA_VALUE visibility.
  The heuristic is not a complete ASN.1 parser; do not claim arbitrary private
  object protection. All sessions share the store and upstream ignores PINs.
- Allocator uses calloc(1,size)/free; logging is disabled; import-private-key
  support is set to 1 (upstream default), OTA/JITP settings remain disabled.
  Default PIN is the reference config's interoperability constant, not a real
  access control or a credential provisioned by init.
- RNG is unchanged: upstream Mbed TLS CTR-DRBG with platform entropy. On Linux,
  Mbed TLS uses getrandom when available, falling back to /dev/urandom; no
  deterministic or simulated RNG, and no generic-PAL random source.

claims only that process's module usability. exec performs no module preflight:

have independent stores; a proxy token belongs to the daemon's loaded backend,
not the health/client process. Pinned proxy a348a5f59b535b1ca309ea9f0a722e3bec692f72

daemon process. max_contexts=1 is admission, not isolation. Independent shards,
clients and domains need independent daemon/provider processes. Close/finalize
