Virt-card patch patches/0001-virtcard-without-sanitizers.patch:
migrated byte-identical from the pkcs11-check-ws workspace
(github.com/mingulov/pkcs11-check-ws,
docker/ykcs11-canokey/patches/, added in 8f64c0e, last touched in
4edfd88; no license file at the workspace root and no grant header
in the patch file, so its own license stays UNREVIEWED). It exposes
upstream's own u2f-virt-card target definition under the existing
VIRTCARD option instead of ENABLE_TESTS, which would otherwise force
AddressSanitizer/UBSanitizer flags onto a driver pcscd dlopen()s; a
sanitizer-instrumented driver aborts inside pcscd and yields no
readers. This is a build-system provisioning extension: the
ENABLE_TESTS path is untouched, no card or PKCS#11 semantics change,
and the build fails closed if the driver links sanitizer runtimes.
A declared patch that fails to apply fails source resolution before
any build starts.

Virt-card patch patches/0002-virtcard-quiet-ifd.patch is P11Lab-authored
for this recipe (SPDX-License-Identifier: Apache-2.0, same as the
recipe). It guards the seven unconditional IFD entry-trace printfs in
virt-card/ifdhandler.c with VIRTCARD_TRACE_IFD (default off); the
anomaly warnings stay unconditional. Without it every APDU appends
pcscd.log lines in-process and long operations trip the supervised
64 KiB service-log bound. Log output only: no APDU, protocol,
card-state or PKCS#11-visible change. This is a provisioning/log-hygiene
extension, not a semantic change.

Daemon closure ships as exact extracted Debian package bytes, not
rebuilt sources: 7 whole packages (pcscd, openssl, libpcsclite1 plus
the proven link closure), audited with ldd receipts. Whole-package
/usr/share/doc copyright files ship inside the image. libccid (USB
driver bundles) and the polkitd/dbus daemons are installed in the
builder to satisfy dependencies but never extracted: nothing links
them, and no USB driver may be visible to pcscd. The p11-kit PKCS#11
build header has a permissive unrestricted-copy notice and the
libpcsclite headers ship under their package copyright; both
headers' notices are retained. libp11-kit itself is not linked.
